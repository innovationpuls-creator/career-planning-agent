# 前端页面与组件模式

本文档补充 `docs/Design.md`，用于约束页面类型、组件使用、图表色板和常见状态。它仍然不是 token 数值清单；具体值以源码为准。

## 基本规则

- 先判断页面类型，再选择布局和组件模式。
- 优先使用已有项目封装组件；缺失能力时先确认需求，再补封装或使用 Ant Design 原组件。
- 页面样式必须 token 化，不在页面组件里发明新颜色。
- 页面越偏业务操作，越要收敛氛围装饰；页面越偏生成、报告、登录注册，越可以使用沉浸式表达。

## 页面类型

### 高沉浸任务页

适用页面：登录、注册、生成报告、关键初始化流程。

设计目标是让用户感知“系统正在运行，用户正在做关键决策”。可以使用深色系统侧、暖纸交互侧、玻璃卡片、环境光、spotlight 和低调工具日志。

注意事项：

- `55:45` 只作为高沉浸分屏参考，不是全站布局规则。
- 工具日志必须对应真实能力或真实阶段，不能写虚假工具名。
- 玻璃不应遮挡表单、CTA、错误提示和可读文本。
- 移动端优先保证表单可用性，再保留氛围。

### AI 教练对话页

适用页面：`/coach`。

设计目标是让对话成为第一主角。聊天区占主导，历史消息、会话列表、记忆、工具轨迹和上下文状态保持辅助。

布局建议：

- 主对话区约占 70% 到 80%。
- 历史会话或消息侧栏约占 20% 到 30%。
- 工具轨迹可以折叠、抽屉化或作为消息内的低干扰状态展示。
- 上传、停止生成、重试、复制等操作要贴近对话流。

### 学生工作台页

适用页面：`/home-v2`、`/student-competency-profile`、`/career-match`、`/snail-learning-path`、`/personal-growth-report` 的编辑和浏览态。

设计目标是帮助学生理解当前状态、下一步和完成路径。

模式建议：

- 顶部展示当前目标、进度、关键指标和主要 CTA。
- 中部承载任务流、Tab、对比、建议、资源或报告章节。
- 复杂流程使用明确步骤、状态标签、保存反馈和错误恢复。
- 氛围元素可以存在，但不能压过任务信息。

### 管理员数据页

适用页面：`/admin/*`。

设计目标是高效扫描、筛选、查看、编辑和确认。

模式建议：

- 筛选区、统计区、表格区、详情弹窗或抽屉要层级清楚。
- 表格密度可以高于学生端页面。
- 文案直接说明字段、状态、错误和风险。
- 不使用诗性标题、沉浸式终端或大面积玻璃叙事。
- 删除、重置、禁用等操作必须有明确确认反馈。

### 图表与知识图谱页

适用页面：岗位能力图谱、同岗行业对比、管理员统计分析页。

设计目标是清晰比较和发现趋势。

模式建议：

- 图例、轴标签、tooltip、选中态和空数据状态必须清楚。
- 多系列图表不得只使用品牌主色的深浅变化。
- 图谱页面要有选中态、悬停态、聚焦态和说明面板。
- 图表颜色可以丰富，但必须来自集中定义的 chart token 或图表主题。

## 组件规则

### 表单与输入

强制优先使用：

- `ClaudeInput`
- `ClaudePassword`
- `ClaudeSelect`
- `ClaudeButton`

表单字段、校验、禁用、加载和错误状态必须清楚。上传使用 `FormData` 对应后端 `UploadFile` + `Form`，视觉上遵守项目 token。

如现有封装无法表达需求，先确认需求，再选择：

- 扩展现有 Claude 组件。
- 新增同风格封装组件。
- 临时使用 Ant Design 原组件，并说明原因。

### 按钮与操作

主操作使用 `ClaudeButton` 的品牌主强调变体。次级操作使用低干扰变体。危险操作使用明确的危险语义，不要只依靠颜色表达风险。

页面中只能有少量主 CTA。多个操作并列时，按“主操作、次操作、危险操作、取消”建立视觉层级。

### 卡片与表面

卡片用于承载独立信息块、工具面板、重复列表项、弹窗内容或关键步骤。不为了装饰而把每个页面区块都做成卡片。

不要卡片套卡片。需要分组时优先使用标题、分割、间距、Tabs、Steps 或表格结构。

玻璃表面只用于高沉浸场景或关键任务容器。普通后台和数据页使用更克制的暖色容器。

### Tabs、Steps 与导航

Tabs 用于同一对象下的平级视图切换。Steps 用于顺序流程和完成状态。不要把流程步骤伪装成 Tabs，也不要把平级视图伪装成 Steps。

可访问性要求：

- Tab 需要表达当前选中态。
- 禁用状态必须真实禁用并有视觉反馈。
- 动效不能阻碍键盘操作。

### 表格与筛选

管理员页和岗位数据页优先使用表格。筛选区应放在表格上方，搜索、重置和新增操作位置稳定。

表格必须处理：

- 加载中。
- 空数据。
- 后端错误。
- 分页。
- 长文本截断或详情展开。
- 危险操作确认。

### 弹窗、抽屉与详情

新增、编辑、小型确认优先使用 Modal。字段较多、详情较长或需要并排信息时优先使用 Drawer。

详情内容不要只堆 JSON。应按业务字段分组，保留可读标签和空值说明。

## 图表色板

数据可视化可以使用更丰富的颜色，但必须遵守以下约束：

- 图表颜色集中定义为共享 chart token 或图表主题。
- 页面组件不得直接写图表色值。
- 品牌主色用于当前选中、关键系列或强调点，不用于所有系列。
- 多系列图表应具备足够区分度，并考虑色弱可读性。
- 成功、警告、错误等语义颜色应沿用全局语义 token。
- 如果现有源码没有可用 chart token，新增图表前必须先补共享 chart token，并同步更新本文件。

建议集中定义这些语义槽位：

- `categorical`：离散分类序列。
- `sequential`：连续数值或强弱层级。
- `diverging`：正负、优势/劣势、提升/下降。
- `highlight`：选中、当前、推荐、重点。
- `muted`：背景系列、参考线、历史数据。
- `grid`：网格线、轴线、辅助边界。

## 状态模式

### 加载

加载状态要说明正在加载什么。流式任务要展示阶段或最新事件，避免只有无意义 spinner。

### 空状态

空状态要说明为什么为空，以及用户下一步能做什么。不要写泛泛的“暂无数据”后就结束。

### 错误

错误状态要说明失败对象、失败原因或可恢复动作。接口错误可以显示简短提示，详情可放入可展开区域或日志。

### 成功

成功反馈应短暂、明确、低干扰。关键提交成功后可以跳转或刷新，但要避免状态刚出现就消失。

### 禁用

禁用状态必须有真实业务原因。能解释时提供 tooltip、辅助文字或前置条件提示。

## AI 开发检查清单

实现或修改 UI 前，必须确认：

- 页面属于哪种类型。
- 是否读过对应功能文档和现有源码。
- 是否使用项目封装组件。
- 是否需要新增共享 token，而不是写页面私有颜色。
- 管理员页是否保持数据优先。
- AI 教练是否保持对话优先。
- 图表是否使用集中定义色板。
- 文案是否准确清楚。
- 动效是否可降级。
