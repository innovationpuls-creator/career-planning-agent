# 前端设计语言总纲

本文档是 AI 开发本项目 UI 时的总入口，用来约束设计判断，避免临时猜测、随意发明样式或把单页经验误当作全站规则。

它不是完整组件规格书，也不是运行时 token 的副本。具体 token、组件实现和动效值以源码为准；本文档只描述使用原则、页面分型和决策边界。

## 读取顺序

1. 先读本文件，确认整体设计语言和不允许越界的规则。
2. 需要页面、组件、表格、图表、状态模式时，读 `docs/Design-patterns.md`。
3. 需要具体功能、路由和页面到后端接口映射时，读 `docs/UI功能模块/README.md`，再进入对应模块文档。
4. 需要运行时样式值时，查源码：
   - `myapp/config/defaultSettings.ts`
   - `myapp/src/styles/claude-tokens.ts`
   - `myapp/src/styles/motion.ts`

如果文档和源码出现不一致，源码是当前事实。不要把本文档里的描述反向当作 token 真值。

## 定位

项目整体气质是温暖、安静、智能、可信、可触摸。认证页建立了品牌气质参考：深色系统感表达智能体、推理和后台运行；暖纸与玻璃表达用户输入、决策和可操作界面。

这个参考不是要求所有页面都做成左右分屏，也不是要求所有页面都使用终端日志。它提供的是品牌方向：理性但不冰冷，智能但不炫技，温暖但不松散。

## 全站原则

所有新增或修改页面都必须遵守以下原则：

- 不猜测样式、接口、页面功能或数据形状；不明确时先读文档和源码，仍不明确就提问。
- 样式使用 `antd-style` 的 `createStyles(({ css, token }) => ({ ... }))`。
- 颜色优先使用 `token.*`、`claudeColors.*`、`claudeGlass.*` 和已有共享 token。
- 不在组件文件中临时硬编码新的 hex、rgb、rgba、hsl 或 named color。
- 需要透明度时优先用共享 helper 从既有 token 派生。
- 表单控件和按钮强制优先使用项目封装的 `ClaudeInput`、`ClaudePassword`、`ClaudeSelect`、`ClaudeButton`。
- 只有现有封装无法表达需求时，才使用 Ant Design 原组件；使用前必须确认原因，并保持 token 化样式。
- 不新增 `.less` 或 CSS modules，除非已有文档明确说明是 Ant Design 或 Mako 的必要 workaround。
- 动效使用 `motionTokens` 或既有场景 token，并尊重 `prefers-reduced-motion`。
- 文案以准确、克制、清楚为主；功能文案不追求诗意，不牺牲可读性。

## 色彩方向

`terracotta` 是主要品牌强调色，用于主按钮、当前状态、关键标注和少量品牌锚点。不要把蓝色扩展为按钮、导航、选中态或主要品牌色。

常规界面以暖纸、象牙白、暖灰和低对比边框为基础。深色区域用于系统感、智能体运行态、终端式反馈或高沉浸场景，不作为每个页面的默认背景。

数据可视化允许使用比品牌 UI 更丰富的图表色板，但必须集中定义为共享 chart token 或图表主题，不允许在单个页面里临时写色值。图表色板规则见 `docs/Design-patterns.md`。

## 页面分型

### 高沉浸页面

登录、注册、生成报告等页面可以使用“系统侧 + 用户侧”的对照式空间。认证页的 `55:45` 分屏、终端隐喻、暖玻璃、鼠标 spotlight 和环境光斑，只属于这类高沉浸体验的参考范式。

不要把 `55:45` 分屏扩展为全站默认布局。只有页面目标确实需要表达“系统正在运行，用户正在决策”时，才使用这种叙事结构。

### AI 教练页面

AI 教练以对话界面为主。历史消息或会话侧栏只占辅助比例，通常约为 20% 到 30%。工具轨迹、记忆和智能体状态应服务于对话理解，不应压过主聊天区。

### 学生工作台页面

职业规划首页、简历解构、职业匹配、学习路径、报告编辑等页面以任务完成为主。它们应继承温暖、智能、清晰的品牌气质，但不需要复制认证页的终端与大玻璃卡片。

这类页面优先保证流程、信息层级、CTA、进度状态和数据可读性。

### 管理员页面

管理员页面数据为主。布局应更紧凑、更适合扫描、筛选、分页、查看详情和批量理解。可以使用项目色彩和组件规范保持一致，但不要强行加入沉浸式终端、诗性文案或大面积玻璃氛围。

### 图表与图谱页面

图表、雷达图、柱状图、饼图、知识图谱和趋势洞察优先保证辨识度、图例清晰、交互反馈和颜色区分。品牌强调色不能承担所有数据系列。

## 排版与文案

标题性、氛围性内容可以使用 serif 字体和适度字距。功能界面、表单、表格、筛选器、错误提示和正文说明使用 UI 字体，保持普通字距和稳定行高。

中文文案可以克制、有留白，但不能为了气质牺牲明确性。管理员页面、错误提示、删除确认、表格字段、筛选条件和 AI 状态提示应直接说明事实和操作结果。

## 组件边界

视觉外壳负责空间、材质、光照和品牌语气；业务内容负责字段、数据、校验、提交和状态。不要把复杂业务逻辑写进视觉壳组件，也不要让业务组件重复实现同一套背景、玻璃、光照或基础排版。

只在确有复用价值时提取抽象。不要为了“统一设计”提前制造过度组件。

## 高沉浸范式来源

认证体验是当前高沉浸范式的参考实现，相关源码包括：

- `myapp/src/pages/user/layout.tsx`
- `myapp/src/pages/user/components/`
- `myapp/src/components/auth/`

认证页中的终端日志、注册步骤、登录/注册 morph、`55:45` 分屏、Mac 三色点和鼠标 spotlight 是该范式的具体实现，不是全站默认组件规范。

## 验收口径

当 AI 开发新 UI 时，验收重点是：

- 是否先读了相关功能文档和源码，而不是猜页面行为。
- 是否使用共享 token 和项目封装组件，而不是临时写样式。
- 是否按页面类型选择了合适布局，而不是把认证页全量复制到所有页面。
- 是否在管理员和数据页优先保证数据可读性。
- 是否在图表页使用集中定义的图表色板，而不是随手写颜色。
- 是否避免文档和源码 token 值互相漂移。
